## Ce qui a bien marché

- **Boucle serrée retour → diagnostic → fix → preuve.** Chaque correctif vérifié avec une vraie mesure : timing du flux SSE en `curl`, screenshots, tests stub déterministes. Pas de « c'est corrigé » sans preuve.
- **Discipline de diagnostic.** Le « board a posteriori » n'a pas été corrigé à l'aveugle : reproduit, puis **2 causes racines** trouvées (le modèle n'émettait pas la ligne `BOARD:` ; le parser live cassait sur une ligne vide). Le transport SSE, lui, marchait — vérifié avant de toucher quoi que ce soit.
- **Testabilité par extraction.** Logique pure sortie dans `lib/format.ts` → 16 tests rapides et stables.
- **Livraison par phases.** Gros chantier (refonte) découpé en 3, chaque phase vérifiée avant la suivante. Le hero (réversible) d'abord, la plomberie ensuite.
- **Mode démo comme surface E2E hermétique** + interception des appels externes (TTS) dans les tests.

## Ce qu'on doit améliorer / risques ouverts

- **Le protocole par marqueurs texte est le maillon faible.** Le modèle classe « projet vs quotidien » et émet la ligne `BOARD:` de façon **non déterministe** → le moment magique n'est pas garanti (un vrai projet peut partir en `direct` sans GO). *La vraie réponse = sortie structurée (tool/JSON).*
- **Couverture de test en trous.** Need card + GO vérifiés par **stub / manuel** (non-déterminisme LLM), pas en E2E hermétique. Les états dépendants du micro (`listening`/`crystal`) ne sont **pas testables en headless** (Chromium sans moteur vocal).
- **Dette introduite, assumée** : `qform` gardé comme repli (coupe à moitié), CSS mort (`plan-card`/`plan-step`), `NoteView` désormais démo-only, la persistance ne couvre pas `launchNote`/`plan` (refresh en plein cadrage → on perd le GO).
- **Support STT = Chrome/Edge.** Le hero vocal dégrade sur Safari/Firefox → besoin d'un repli (Deepgram est dans l'env) ou d'un fallback gracieux mis en avant.

## Leçons à graver (process)

- **Bug « a posteriori » / de timing → toujours reproduire avec une mesure réelle du transport** avant de patcher (ici : `curl -N` horodaté a évité de « corriger » un faux problème de buffering).
- **Protocole piloté par un LLM → prévoir un chemin de stub déterministe** pour tester le front indépendamment du modèle.
- **Garder le mode démo comme surface E2E hermétique** ; gater les appels externes (TTS, run) dans les tests.

## Métrique à instrumenter (PO)

**Taux « premier message → GO »** sur nouvelles sessions. Seuil go/no-go : **≥ 30 % sur les 50 premières sessions organiques** (hors démo, hors fondateur).
